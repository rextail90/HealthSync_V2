# HealthSync

A cross-platform fitness tracker built with Flutter and Firebase. You can log workouts in real time, save reusable workout templates, track daily macros against your goals, and look back through past sessions.

Built by a team of students in May 2024. See the [contributors page](https://github.com/rextail90/HealthSync_V2/graphs/contributors) for who worked on it.

## Features

- **Accounts.** Email/password sign-up and login through Firebase Authentication. There is also a guest "Skip" mode.
- **Quick workouts.** Start a timer, add exercises as you go, and check them off as you finish them.
- **Workout templates.** Build a routine once (exercise, sets, reps) and start it with one tap.
- **Persistent timer.** If you leave a workout screen, the timer keeps running and a bar at the bottom of the Exercise tab takes you back.
- **Workout history.** Every finished session is saved with its duration and completed exercises.
- **Nutrition tracking.** Enter protein, carbs and fat with daily goals and see a pie chart of how close you are to each goal.
- **Profile dashboard.** Today's macro breakdown and a weekly workout-hours bar chart, both drawn with `CustomPainter`.

## Tech stack

| Layer | Choice |
|---|---|
| UI | Flutter (Material 3), Dart 3 |
| State | [`provider`](https://pub.dev/packages/provider) (`ChangeNotifier`) |
| Auth | Firebase Authentication |
| Charts | Hand-written `CustomPainter`, no chart library |
| Platforms | Android, iOS, web, macOS, Windows |

## Project structure

```
lib/
├── main.dart                  # App entry, providers, login screen, tab shell
├── firebase_options.dart      # Generated by FlutterFire CLI
├── providers/                 # App state (ChangeNotifier classes)
│   ├── timer_provider.dart          # Workout stopwatch shared across screens
│   ├── quick_workout_provider.dart  # Exercises queued in a quick workout
│   ├── workout_template_provider.dart
│   ├── history_provider.dart        # Completed sessions
│   └── nutrition_data_provider.dart # Today's macros
├── screens/                   # One file per screen/tab
└── widgets/                   # Shared UI: macro pie chart, add-exercise dialog
test/                          # Unit and widget tests
```

### How state flows

All app state lives in `ChangeNotifier` providers registered once in `main.dart`. Screens read state with `context.watch` and change it with `context.read`. The bottom tabs sit in an `IndexedStack`, so switching tabs keeps form input and charts in place. For example, entering macros on the Nutrition tab updates the Profile pie chart right away.

The workout timer is a single shared provider. That is what lets the timer keep running while you move between screens and lets the Exercise tab show the running time.

## Getting started

**Prerequisites:** [Flutter SDK](https://docs.flutter.dev/get-started/install) 3.19 or newer, and a device or emulator.

```bash
git clone https://github.com/rextail90/HealthSync_V2.git
cd HealthSync_V2
flutter pub get
flutter run
```

The repo is already wired to the project's Firebase app. To point it at your own Firebase project instead, enable Email/Password sign-in in the Firebase console, then run:

```bash
dart pub global activate flutterfire_cli
flutterfire configure
```

## Testing

```bash
flutter test
```

The tests cover the timer (counting, formatting, reset), the nutrition provider, input validation on the nutrition form, and the pie chart's empty state.

## Limitations and next steps

- Workouts, templates, history and nutrition are kept in memory, so they reset when the app restarts. The next step is to store them per user in Cloud Firestore.
- Weekly workout hours are entered by hand. They could be calculated from workout history instead.
- Guest mode skips authentication completely.
